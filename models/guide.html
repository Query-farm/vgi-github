GitHub reporting with Crossfield

This model covers all 15 vgi-github functions: 34 approved metrics, 32 named reports, and the complete detail schemas, including array columns. Business definitions live in build_model.py; source_inventory.json records the worker signatures and field descriptions. The generated package contains the model, named parameters, comments and revision together.

Use the matching patched DuckDB 2.0 engine, Crossfield and native VGI extensions. The community VGI binary for another DuckDB release is not compatible. This profile uses a local subprocess; HTTP transport has not been qualified here.

Attach and discover

Run from this checkout. Replace the worker project path with its absolute path:

LOAD vgi;
LOAD crossfield;
SET TimeZone = 'UTC';

ATTACH 'github' AS github_source (
  TYPE vgi,
  LOCATION 'uv run --project /absolute/path/to/vgi-github vgi-github',
  token_source 'gh', auth 'required',
  reporting true, operation_timeout_seconds 120
);

ATTACH 'models/github-reporting.package.json' AS engineering (
  TYPE crossfield,
  BINDINGS '{"github_source":{"catalog":"github_source","provider_id":"queryfarm.vgi.github","instance_id":"github.com"}}'
);
SET crossfield_mode = 'strict';

SELECT * FROM crossfield_queries()
WHERE database_name = 'engineering';

SELECT * FROM crossfield_query_parameters()
WHERE database_name = 'engineering' AND query_name = 'pr_merge_summary';

The logical binding github_source is independent of the attachment alias. The model requires the attachment's reporting policy, 120-second worker budget and API origin to match. The package scopes identities to github.com; generate a separately reviewed package for another instance. A token, credentials and private repository names are never stored in the model.

Every report argument is required. SQL date arguments are ISO strings; native prepared parameters use the declared DATE type. NULL and invalid typed values reject. Empty or reversed intervals use ordinary SQL semantics: an empty cohort, zero ungrouped counts and NULL duration statistics.

Start with merges

SELECT * FROM engineering.reports.pr_merge_summary(
  repository => 'Query-farm/crossfield',
  start_day => '2026-09-01', end_day => '2026-10-01'
);

SELECT * FROM engineering.reports.merged_pr_detail(
  repository => 'Query-farm/crossfield',
  start_day => '2026-09-01', end_day => '2026-10-01'
);

EXPLAIN (SEMANTIC)
SELECT * FROM engineering.reports.pr_merge_summary(
  repository => 'Query-farm/crossfield',
  start_day => '2026-09-01', end_day => '2026-10-01'
);

The cohort is merge time in [start_day, end_day) in UTC. Bots remain included. Elapsed hours use millisecond differences divided by 3,600,000, so draft and waiting time count. This is not review time or business hours. Four merge durations of 2, 4, 10 and 20 hours produce 4 merged PRs, mean 9, median 7 and continuous p90 17. Empty cohorts return 0, NULL, NULL, NULL. The detail report returns the same population, preserving each PR identity.

pr_merges_daily groups that cohort by UTC merge date; absent dates stay absent. pr_merges_by_author groups by the reported login. Do not average their means or percentiles to recover an overall figure; ask for pr_merge_summary.

Reporting coverage

Reports Definition
pr_overview, pr_merge_summary, pr_merges_daily, pr_merges_by_author, merged_pr_detail Complete PR listing, current state or explicitly selected merge-date cohort.
issue_backlog, issue_closure_summary Issues exclude PRs. Backlog is current; closure duration uses the currently recorded closure, including any reopening history in elapsed time.
ci_summary, ci_by_workflow Runs created in the UTC interval, using each run's latest reported attempt. Reliability is success / (success + failure + timed_out); cancellation/skipped/other outcomes are excluded; zero denominator is NULL.
repository_activity Complete PR and CI populations independently aggregate at requested repository before combination. All visible history and current outcomes; no fact-to-fact multiplication.
commits_summary Listed default-branch commits by committer UTC date and signature verification. Not all branches or deployment frequency.
release_summary Published stable releases/prereleases by publication date. Downloads are current lifetime asset counters for those releases, not downloads during the interval; generated source archives are excluded.
contributors_summary GitHub's current default-branch attribution, not interchangeable with commit-history counts.
languages_summary Current language bytes, not lines of code.
stars_summary Current visible stargazers; removed stars disappear. The worker requires administrator access.
repository_summary, account_repository_summary Current stars/forks for one repository, or a complete visible owned-repository count for one account.
<function>_detail All 15 functions expose their complete field schemas. Search reports are capped discovery and all_rate_limit_detail is diagnostic; neither has approved aggregate metrics.

Report and column comments expose population choices through Crossfield discovery. Array-valued labels, reviewers, assignees, topics and commit parents remain detail values; their elements do not multiply the source grain. Current worker objects are flattened fields, so this model does not invent STRUCT columns.

Completeness, failures and limits

Reporting mode requires max_rows => 0 for keyed listings and the model fixes that argument. Missing/inaccessible sources, exhausted page bounds, malformed required identities/timestamps/counters and provider errors raise exceptions. It disables result caching and stale-on-error reuse. Source pages may still be conditionally revalidated using ETags. An empty accessible listing can return zero; a missing repository cannot masquerade as one.

Complete means all rows visible through the selected endpoint and credentials, within the worker's 100-page bound and the model's 10,000-row source ceiling. Large populations that exceed bounds fail. SQL LIMIT is a presentation operation, not a completeness proof. Consume every result successfully before treating it as a completed report: native execution may deliver rows before a later error.

GitHub offers no transactional snapshot across these requests. Changing data between pages or independently fetched facts remains possible. Repository names and logins are mutable labels; numeric IDs and composite source grains retain identity within the configured instance. This is live execution, not historical AT or materialized reporting.

Search can return at most 1,000 selected matches and GitHub may mark responses incomplete. Its reports provide discovery rows, not approved totals. First-review latency, historical reopened backlog, exact workflow completion duration, deployment frequency, code churn and lost-star history need additional facts. Calendar smoothing/window reports are not published for this invocation profile.

Rebuild and test

Generate on the build host using only the Python standard library:

python models/build_model.py

This writes the standalone invocation model, reports.json and portable package. Changing an API instance uses --instance and --api-origin and receives a separate package identity. Review its policies and use --revision to advance the revision before distributing changed definitions for an existing instance. The package has no publication receipt (checks: []); attachment validates its definitions, while deterministic tests supply implementation evidence.

The SQLLogicTest suite runs the real worker and native VGI/Crossfield against an independently authored mock HTTP API. Fixture notes specify expected answers and errors. Python implements the worker/HTTP fixture; all SQL executes in native DuckDB. The worker's reporting tests separately exercise pagination, validation, cache policy and deadlines. Exact build commands and current results belong in the integration notes.
